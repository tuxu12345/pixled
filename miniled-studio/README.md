# Mini-LED 背光分区调光 Demo

> 跑起来：`node server.mjs 8140` → http://127.0.0.1:8140/

## 这个东西和「点阵屏 demo」是两回事

我另有一个 `led-studio`（HUB75 点阵屏模拟器）。那个是**显示屏**：像素间距 3~5mm，一颗颗灯珠肉眼可见。
**Mini-LED 是背光**：像素间距 0.1~0.5mm，你看不到它，它的作用是给 LCD 打光。

```
HUB75 点阵屏          Mini-LED 背光
─────────────         ─────────────
像素 = 灯珠本身        像素 = LCD 透光率 × 背光
扫描驱动 + DMA         分区调光 + 扩散
看的是"图案"            看的是"分区怎么给光"
```

---

## 核心成像模型

```
最终画面 = LCD 透光率(像素级) × 背光亮度(分区级，被扩散糊开)
                    ↑                        ↑
          像素级精度，能精确挡光      分区级精度，只能大块给光
```

**Mini-LED 的全部价值与代价都来自这个"精度不匹配"**：

| | 传统侧光式 (edge-lit) | Mini-LED 分区调光 |
|---|---|---|
| 背光 | 一整片，全屏一个亮度 | 切成几百~几千个分区，各自调亮度 |
| 暗场 | 压不下去（背光还是全亮） | 该暗的区域独立压暗 |
| 代价 | —— | **光晕 blooming**（背光糊开了，LCD 只能按像素挡光） |

## 结论（都是实测数据，不是想当然）

这一节我改过三次。**最初我以为 Mini-LED 的卖点是"黑得更黑"，测完发现不准确。**

### ✓ 真正的收益是「还原精度 + 省电」

夜景窗户场景（暗房间 + 亮窗），32×18 分区：

| 指标 | 传统整屏 | Mini-LED | 改善 |
|---|---|---|---|
| **重建误差 MAE** | 0.0266 | **0.0035** | **准了 7.5×** |
| **背光功耗** | 85.3% | **22.7%** | 只剩 27% |

像素级验证（同一位置的输出值）：

| 位置 | 原图 | 传统整屏 | Mini-LED |
|---|---|---|---|
| 暗房间 | `8,8,9` | `2,2,2` ✗ 压过头了 | **`8,8,10`** ✓ |
| 亮窗 | `255,162,100` | `240,152,94` ✗ 没还原准 | **`255,162,100`** ✓ |

**Mini-LED 在暗处和亮处都精确还原了原图。** 省电的本质是：每块区域只给自己需要的背光，多余的一分不给。

### ✗ 我原来那个论断错在哪

"分区调光让黑更黑" —— 不严谨。背光经扩散膜会串到邻区，所以按"暗部平均亮度"算，
分区模式甚至**略高**（多了底光泄漏）。黑场下限其实由**面板漏光**决定，不是分区数。

### ✓ 光晕是物理必然

背光没法像素级精确 —— 背光板有导光板和扩散膜，光会横向串。这是物理限制，不是算法缺陷。
实测规律：
- **分区越多 → 光晕越小、格子感越弱**（12×8 → 96×54：MAE 0.0059 → 0.0028）
- **扩散越大 → 边界越柔和，但光晕范围越大**

### ✓ max / mean 的取舍

| 算法 | 行为 | 代价 |
|---|---|---|
| `max` | 取区块最亮像素 → 保住高光不裁切 | 功耗高（实测 6.1% vs 4.5%） |
| `mean` | 取平均 → 省电 | 含高光的分区被平均低 → 高光被吃掉 |
| `rms` / `hybrid` | 折中，厂商常用（hybrid 可调 max 权重） | —— |

## Demo 里能玩的

**7 个测试画面**，每个能暴露不同问题：
- 星空 / 黑底亮斑 → 看暗场
- 白字黑底 / 晚间窗户 → 看光晕
- 灰阶渐变 → 看格子感（分区边界最容易露馅的地方）
- 彩色高饱和 → 看颜色会不会被背光带偏

**可调参数**：
- 分区数（2×2 到 128×72，另有 5 个预设：96 / 384 / 1152 / 2304 / 9216 分区）
- 取值算法（max / mean / rms / hybrid）+ hybrid 的 max 权重
- 背光扩散半径、分区最低亮度、整体提亮
- 面板特性：漏光、原生对比度、伽马

**三种视图**：三图对比 / 只看传统 / 只看 Mini-LED
**两个开关**：叠加分区网格（看分区边界）、显示背光场热力图（看"幕后"）
**导出**：对比报告 txt（含全部实测数字）

## 代码结构

```
miniled-studio/
├─ index.html
├─ server.mjs         静态服务
├─ css/app.css
└─ js/
   ├─ pipeline.js     核心算法：分区提取 / 背光扩散 / 成像 / 对比度
   ├─ patterns.js     7 个测试图案（纯程序生成，不依赖外部图片）
   ├─ render.js       渲染 + 指标（重建误差 / 光晕 / 格子感 / 功耗）
   └─ app.js          UI 控制器
```

### 建模时踩过的坑（都记下来免得再犯）

1. **函数不能叫 `process`** —— 会遮蔽 Node 全局 `process`，报错是 `process.exit is not a function`。改名 `processFrame`。
2. **漏光必须是加性的**，不能当除数。物理上 LCD 关不严，背光再暗也有一点光透出来 ——
   所以黑场亮度 ≈ leak（常数），这才是"面板原生对比度"的根源。
3. **全局背光基线要自适应**，不能写死 1.0。真实电视会按画面调全局背光，
   写死 1.0 对暗场画面是冤枉，对比就失去意义。
4. **hue 抖动到暗部会翻转排序** —— 分区取值算法要相对排序，不能用绝对值硬比。
5. **格子感的"阈值占比"指标不可靠** —— 阈值本身在噪声量级，测出来全是 99%。格子感交给眼睛看。

### 指标选择的教训

- 测"光晕"要用**亮暗紧邻**的画面。用 `split`（左右对半）测过，暗区离亮区太远，
  扩散传不过去，三种分区数都测出 0 —— 测了个寂寞。
- 测"高光还原"要看**峰值/高光区均值**，不能看 RMSE：
  成像里透光率被截断到 1，高光像素被"精确"还原，RMSE 恒为 0。
- **不是所有画面都有精度收益**。`text`（白字黑底，几乎全黑）的全局背光自适应后已经够用，
  分区调光精度没提升空间 —— 但**省电依然成立**（100% → 20%）。这是诚实的物理结果。
