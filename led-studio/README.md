# LED Studio · 虚拟点阵屏效果 Demo

点阵 LED 和拼豆是同一件事的两面 —— **都是「离散格子 + 有限色板」**。
拼豆是物理材料版，LED 屏是电子版。所以拼豆的图案库可以直接喂给 LED 屏，这个 Demo 里就有一条通路。

这个 Demo 让你在浏览器里**把一个点阵屏跑起来**：调分辨率、调色深、调屏的观感，
挂各种驱动效果，导入任意**图片或视频**上屏播放，再把结果导出去烧进真实硬件。

## 跑起来

```bash
cd led-studio
node server.mjs 8139
# 打开 http://127.0.0.1:8139/
```

> （页面里做了兜底提示，会告诉你该怎么起服务。）

## 能做什么

### 虚拟屏（把 LED 屏的样子做对）

真实感藏在细节里，这几项缺一个就"不像"：

| 参数 | 说明 |
|---|---|
| 面板尺寸 | 预设 64×32 / 64×64 / **96×48（我们的车屏）** / 128×32 / 32×16 / 128×64，也能手填 |
| 色深 | RGB888 / RGB666 / **RGB565（HUB75 常见）** / RGB332 / 单色琥珀 / 单色蓝 |
| 伽马 | 屏是线性响应的，素材是 sRGB，必须转，否则暗部全糊 |
| 灯珠形状 | 圆形（贴片 LED）/ 方形（模组） |
| 灯珠间隙 | 0~45%。**不留缝就像马赛克，不像 LED** |
| 辉光 | 亮的灯珠会把周围照亮，这是 LED 和印刷品最大的观感差别 |
| 扫描线 | 真实屏是分组扫描的，PWM 下会有细条纹 |

### 驱动效果（10 个）

| 效果 | 用途 |
|---|---|
| **滚动文字** | 点阵屏最经典、也是车外屏最实用的形态。支持彩虹着色 |
| 全屏显示 | 图片/视频原样上屏 |
| 内容横向滚动 | 长图跑马灯 |
| 等离子 | 经典 demo 效果，用来展示色彩深度 |
| 雪花 / 流星雨 | 粒子系统（有风、有拖尾） |
| 扫描线 | 一条亮线扫过画面 |
| 彩虹波 | 渐变流动 |
| 呼吸灯 | 可带中间文字，**到车欢迎灯效就是这个形态** |
| 彩条 / 灰阶测试 | 真机装好第一件事就放这个，验收色深和灰阶 |

每个效果的参数都是实时调的（字号、速度、颜色、粒子数……）。

### 导入图片 / 视频

- **拖进来**或点按钮选文件，图片 JPG/PNG/GIF/WebP，视频 MP4/WebM
- 视频**逐帧实时采样**上屏播放（不预解码，长视频也不吃内存）
- 三种上屏方式：全屏显示 / 横向滚动 / 扫描线扫过
- 采样设置：适配方式（铺满裁切 / 完整装入 / 拉伸）、**抖动**（去色带）、对比度、饱和度、阈值二值化、反相
- **拼豆图案**按钮：直接把隔壁 `pixel-bead-studio` 的图案投到 LED 屏上

### 导出

| 格式 | 说明 |
|---|---|
| 固件 C 数组 | RGB565 调色板 + 索引帧（1 字节/灯珠），可直接编译 |
| 下发帧 RLE | 每 3 字节一段，实测比原始省 75~91%（静态画面） |
| 图案 JSON | 逐像素 hex，前端直接渲染 |
| 录制 WebM | 录当前效果为视频，30fps |
| 导出帧序列 | 按 30fps **确定性**渲染 60 帧 PNG |


## 设计上值得说的几点

**1. 缓冲用 float 而不是 8bit。**
因为亮度、伽马、量化要分开做。一旦提前量化成 8bit 再调亮度，层级就丢了。
粒子/辉光用 `add()` 叠加时值会超过 1，所以**量化时必须先夹到 [0,1] 再做伽马** ——
反过来的话 `1.25^2.2 = 1.63` 被截断到 255，叠加的层次全丢（这个 bug 是测出来的）。

**2. 辉光用"缩小 → 模糊 → 放大叠加"两遍法，而不是逐灯珠 shadowBlur。**
64×64 = 4096 颗灯珠，逐颗开 shadowBlur 会直接卡死。

**3. 时间轴是虚拟的、可冻结的。**
暂停时 `t` 不推进；导出时用 `renderAt(t)` 按固定步长确定性渲染。
所以导出的帧序列和下发的帧是**可复现**的，不依赖当时的渲染时机。

**4. 只有闭着眼睛测不出来的东西才写注释解释"为什么"。**
比如为什么灯珠要留缝、为什么要抖动、为什么 RLE 对等离子反而更大。

## 自测

```bash
node ../_probe/led-pipeline-test.mjs              # 23 项单元测试（缓冲/量化/打包）
node ../_probe/run-headless.mjs led-smoke         # 无头浏览器点遍全部界面（90+ 项）
```

调试钩子（也方便出问题时定位）：

```js
window.__LED_DEBUG__()        // 看内部状态：当前效果、亮灯珠数、内容来源、FPS
window.__LED_RENDER_AT__(2.0) // 确定性地渲染 t=2.0 那一帧，返回亮灯珠数
```

### 无头环境的两个已知限制（不是 bug）

1. **`requestAnimationFrame` 只触发 1 次** —— 所以无头下 FPS 显示 `--`，连续动画看不出来。
   真实浏览器里正常 60fps。自测里用 `__LED_RENDER_AT__` 绕开这一点。
2. **`captureStream(30)` 产出 0 字节** —— 它依赖真实定时器；要用 `captureStream(0)` + 手动
   `track.requestFrame()` 才能拿到帧。录制 WebM 功能本身在真实浏览器里是好的。
