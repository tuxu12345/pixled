两条生成路径的实测对比 为什么默认走分镜

  • 直出 20×20：约 460 token，出图能认出主体；细节（五官）靠模型自由发挥，偶尔崩
  • 直出 48×48：要 8000 token 预算，仍会截断成空串/糊图 —— 不可用于大画布
  • 分镜 20/32/48×48：约 1000~1400 token 全包，48×48 稳定出可辨识图案
  • 为什么分镜更稳：模型只需要决定「16 个形状」，不用逐格生成 2304 个像素；
  • 为什么分镜更好看：边缘由几何算法生成，天然干净、左右严格对称、描边一致
  • 代价：模型无法表达像素级细节，五官必须用「眼睛=深色椭圆+高光椭圆」这类形状显式声明

护栏设计 AI 输出不可信，所以要有这 6 道

  • 抠 JSON：剥掉 markdown、前后废话、尾逗号
  • 尺寸对齐：行列不足自动居中补齐，超出裁剪
  • 索引兜底：越界 / 非法字符一律当透明，不崩
  • 调色板兜底：模型没给色就套内置豆色卡
  • 对称 / 描边修复：拼豆风的关键视觉自动补
  • 落色：颜色吸附到真实可购买豆色，避免"生成的画拼不出来"

数据契约 三方对齐的唯一真相

  • 模型侧（分镜）：cx,cy,w,h 一律 0~1 归一化 + mirror 镜像标记 —— 消除"像素/百分比/角点"歧义
  • 模型侧（直出）：grid 用行字符串 + 单字符索引（0-9a-z，'.' 为透明），比嵌套数组省 3~5 倍 token
  • 应用侧：规整成 {cols,rows,palette,Int8Array}，一份数据同时驱动 UI 预览与导出
  • 固件侧：A5 5A | ver | cmd | cols | rows | colors | flags | RGB565调色板 | RLE | CRC16
  • 压缩：索引帧 + RLE，实测 96×48 从 4608B 降到 522~700B（省 85~89%）

工程化要求 上量产必须补的

  • 密钥安全：Key 只放服务端，客户端走自家 /api/ai/pixel 代理（Demo 里的小圆点：纯前端直连只适合演示）
  • 内容安全：生成内容过一遍审核（车外屏是公共空间，不能出现违规图案）
  • 成本与限流：按账号配额，失败重试有上限；常用图案缓存复用
  • 弱网降级：请求超时 → 内置图案库兜底，绝不让用户对着黑屏等
  • 上车时序：帧下发与手势识别事件共用一条时间轴，避免"门开了图案还没亮"
